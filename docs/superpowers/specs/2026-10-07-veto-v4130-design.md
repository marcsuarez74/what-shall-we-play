# Conception — Le veto ❌ (v4.13.0)

**Date** : 2026-10-07 · **Statut** : validé par le client (maquette v2 : « 1 veto par joueur et par partie, veto nommé, on garde le 👍 : ok »)
**Maquette validée** : `mockup/2026-10-07-v4130-veto.html`

## 1. Décisions

- **Où** : toucher une boîte → la fiche du jeu (bottom-sheet existante) → « ❌ Mettre un veto —
  pas ce soir », au-dessus de « Retirer de la partie ». Aucune page, aucun nouvel écran.
- **Effet** : le jeu sort du pool du tirage (« Tous » comme « Votés »), quel que soit le nombre
  de 👍. Les 👍 sont **gardés** : ils reviennent si le veto est retiré.
- **Sur l'étagère** : boîte grisée, le badge 👍 devient « ❌ prénom » (visible de tous).
  Sous « Lancer » : « N jeu(x) écarté(s) par veto » ; tous écartés → « Lancer » désactivé.
- **Un veto par joueur et par partie** (contrainte `UNIQUE(night_id, user_id)`), **nommé**,
  **révocable** par son auteur seulement, jusqu'au lancement (figé comme les votes ensuite).
  Un jeu déjà écarté ne peut pas être re-vetoé par un autre joueur.
- On **garde 👍** (pas de ❤️) : aucune migration.
- Les **invités par lien** vetoent comme les joueurs (même identité que leurs votes).
- Une boîte retirée de la partie emporte son veto (comme ses votes).

## 2. Modèle et serveur

```sql
CREATE TABLE game_vetos (night_id → nights, game_id → games, user_id → users (CASCADE),
  created_at, UNIQUE(night_id, user_id));
```

- `lib/nights.ts` : `getShelfVetos`, `toggleNightVeto` (gardes du vote : 404 / 403 joueur /
  409 figé / 403 hors étagère ; 409 quota atteint ou jeu déjà écarté).
- `POST /api/nights/[id]/veto { gameId }` (session joueur ou invité, comme `/votes`).

## 3. Interface

- `ShelfRows` : prop `vetos` (jeu → prénom) ; `GameSheet` : prop `veto` (4 états : libre,
  le mien, celui d'un autre, mon veto déjà posé ailleurs).
- `ShelfClient` et `InviteSoiree` branchent l'un et l'autre ; le pool exclut les jeux vetoés.
